## 0. 总体结论与前提

- PRD v1.0 明确「v1.0 仍允许本地离线数据驱动，不要求后端或实时 API」（需求说明 6.1），MVP v0.1 明确「无需先建设后端」；PRD 15 节进一步要求「当前数据规模可本地过滤排序，不为列表额外引入服务端依赖」。
- 因此**后端整体属于「新增假设，待产品确认」**：App 保持本地优先（搜索、筛选、排序、收藏、最近查看全部留在客户端），后端最小职责收敛为三件事——**内容数据下发、版本与更新、健康检查**，作为纯本地模式的演进备选，而非 v1.0 必需组件。
- 数据口径完全以现有 `demo-0.1.json` 为准：后端不新增任何 PRD 未定义的端点、权限或表结构；凡由本方案提出、PRD 未定义的能力（本方案的全部接口与新增字段），均显式标注「**新增假设，待产品确认**」。
- 不引入数据库、缓存或其他新中间件：MVP 数据以版本化静态数据包文件下发（理由与引入条件见 6.4）。
- 技术栈沿用 Java / Spring 生态：Spring Boot 单体应用、Maven 构建、经典分层（controller → service → repository）、统一响应包装与集中错误码。

## 1. 职责边界

### 1.1 后端做（MVP 最小闭环）

| 职责 | 说明 |
| --- | --- |
| 内容数据下发 | 将版本化的内容数据包（`demo-0.1.json` 及后续 datasetVersion）原样透传给客户端，含元信息与完整包下载 |
| 版本与更新 | 提供最新数据包元信息，供客户端启动时比较版本、决定是否下载 |
| 健康检查 | 服务与数据包目录可用性探测，供部署与监控使用 |

### 1.2 后端不做（留在客户端或后续另行立项）

| 不做 | 依据 |
| --- | --- |
| 英雄 / 海克斯 / 装备的查询、搜索、筛选、排序 API | PRD 15：本地可处理，不引入服务端依赖；查询规则（匹配优先级、条件交集）是客户端行为（PRD 第 4 节） |
| 收藏 / 最近查看云同步 | PRD R08：本地存储，键结构与降级行为均已定义在客户端 |
| 账号、注册登录、鉴权体系 | 需求说明 8：不纳入 v1.0 |
| 胜率、榜单、差值的聚合计算 | PRD 12.2：禁止跨条件聚合、禁止互相填补；后端只透传原始计数 |
| 图片下发 | 设计内容清单 9：游戏图片再分发 / 商用授权未核实，图片继续随 App 打包，后端不下发图片（远期如需图片下发，待授权确认后另行评审——新增假设，待产品确认） |
| 实时采集、自动推荐、运营后台 | 需求说明 8：不纳入 v1.0 |

    │   │   │   └── stats/             # PRD 13.2 统计记录模型（v1.0 预留，demo 阶段数据缺失）

    │   └── resources/

| 包 | 职责 | 依赖方向 |
| --- | --- | --- |
| `common.api` | 所有 `/api/v1` 接口的统一响应包装 `ApiResponse<T>`、错误码枚举 `ErrorCode`、全局异常处理收口；错误信息不泄露内部路径与调用细节（PRD 14） | 被所有层引用，不依赖业务层 |
| `common.error` | 业务异常类型（如「数据包不存在」「发布校验失败」），携带错误码 | 依赖 `common.api` 的错误码定义 |
| `common.util` | 纯函数工具：datasetVersion 格式校验、sha256 计算、ISO 8601 时间格式化 | 无业务依赖 |
| `config` | `WebMvc`（CORS、拦截器占位）、`Jackson`（null 保留、ISO 8601）、`content` 目录属性注入 | 仅依赖 Spring |
| `controller` | HTTP 入口与参数校验，只做协议转换，不含业务规则；健康检查与数据包接口在此定义 | → `service`、`vo`、`common.api` |
| `service` | 数据包元信息查询、latest 指针解析、下载流提供、发布校验（引用闭合 / 计数有效性 / 单一数据模式） | → `repository`、`domain` |
| `repository` | `content/` 目录的文件读取：按 datasetVersion 定位数据包文件、读取 latest 指针、计算/读取校验和；MVP 无数据库 | → `domain.dataset` |
| `domain.dataset` | 数据包元信息（datasetVersion、schemaVersion、checksum、downloadUrl 等版本与更新字段） | 无依赖 |
| `domain.content` | 与 `demo-0.1.json` 字段一一对应的内容对象模型；缺失即 null，不猜测补齐 | 无依赖 |
| `domain.stats` | PRD 13.2 统计记录（scopeType / interactionPolicy / baseline 等）；demo-0.1 仅有 wins/games/isSimulated 简化结构，完整字段为 v1.0 预留 | 无依赖 |
| `vo` | 接口出参视图（如 `DatasetMetaVO`），与领域模型分离，字段含义对齐 PRD 12 章防误读规则 | 依赖 `domain` |

## 3. 接口设计

- 前缀：`/api/v1`，HTTP + JSON（UTF-8）。
- 元信息类接口统一响应包装；`download` 接口为数据包原文件直出（大文件不走包装，错误时返回相同错误码结构的简单 JSON body + 正确 HTTP 状态码）。
- 所有响应字段缺失即 `null`，不编造（对齐 PRD「未知项不编造」）。

### 3.1 统一响应包装

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "timestamp": "2026-11-20T00:00:00Z"
}
```

### 3.2 错误码表

| 错误码 | HTTP 状态 | 场景 | 客户端建议处理 |
| --- | --- | --- | --- |
| `0` | 200 | 成功 | — |
| `40001` | 400 | 参数非法（如 datasetVersion 格式不符 `{mode}-{主.次}` 约定） | 提示参数错误，不改本地数据 |
| `40401` | 404 | 请求的数据包版本不存在，或 latest 指针不可用 / 指向不存在的版本 | 回退当前本地数据并提示 |
| `50000` | 500 | 服务内部错误 | 提示稍后重试，保留本地数据 |
| `50001` | 500 | content 目录读取或数据包文件损坏 | 同上；触发服务端告警 |

> 错误码分段约定：`0` 成功；`4xxxx` 客户端侧；`5xxxx` 服务端侧。MVP 不设限流码（无鉴权、无配额，见 6.1）；后续如需再向下分段（如 `40402` 校验和缺失），沿用同一枚举集中维护。

### 3.3 接口清单

| # | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 1 | GET | `/api/v1/health` | 健康检查：服务状态 + content 目录与 latest 数据包可用性 |
| 2 | GET | `/api/v1/datasets/latest` | 最新数据包元信息（客户端启动 / 手动检查更新用） |
| 3 | GET | `/api/v1/datasets/{datasetVersion}` | 指定版本数据包元信息 |
| 4 | GET | `/api/v1/datasets/{datasetVersion}/download` | 下载完整数据包 JSON 文件 |

> 整个接口清单均为「新增假设，待产品确认」：PRD 未定义任何后端接口；R01–R11 全部为客户端本地页面能力，本方案只为其提供「数据从哪来、如何更新」的最小链路。

### 3.4 健康检查示例

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "status": "UP",
    "latestDatasetVersion": "demo-0.1",
    "datasetCount": 1
  },
  "timestamp": "2026-11-20T00:00:00Z"
}
```

- `status` 取值：`UP`（latest 指针与其指向的数据包均可用）/ `DEGRADED`（content 目录异常，服务进程仍在线）。
- 公开响应不含服务器目录路径等内部信息（对齐 PRD 14 与 `common.api` 约定）；目录详情由运维侧本地探查，不下发。
- `datasetCount` 为 content 目录内可正常读取的数据包数，不暴露文件名清单。

content 目录异常路径行为（固定，服务端均触发告警）：

| 异常路径 | `/datasets/latest` | `/health` |
| --- | --- | --- |
| content 目录为空或 `latest.json` 缺失 | 404 + `40401` | `DEGRADED`，`latestDatasetVersion=null`、`datasetCount=0` |
| latest 指针指向不存在的版本 | 404 + `40401` | `DEGRADED` |
| 指向的数据包文件损坏 / 校验和不匹配 | 500 + `50001` | `DEGRADED`，`datasetCount` 为可读包数 |

指定版本接口（`/datasets/{v}` 与 `/download`）不受 latest 异常影响，仍按目录实际内容返回。

### 3.5 数据包元信息示例（`/api/v1/datasets/latest`）

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "datasetVersion": "demo-0.1",
    "schemaVersion": 1,
    "dataMode": "simulated",
    "mode": "demo",
    "gamePatch": null,
    "compiledAt": "2026-11-17T04:28:18.010843+00:00",
    "publishedAt": null,
    "contentChecksum": "sha256:61431afe83b6…（demo-0.1.json 实际校验和示例）",
    "fileSizeBytes": 51449,
    "downloadUrl": "/api/v1/datasets/demo-0.1/download",
    "minClientSchemaVersion": 1,
    "contentPolicy": {
      "stats": "仅人工模拟；无数据保存为 null，不使用站方统计。",
      "lowSampleThreshold": 200
    },
    "snapshots": [],
    "coverage": null,
    "defaultSnapshotId": null
  },
  "timestamp": "2026-11-20T00:00:00Z"
}
```

字段说明：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `datasetVersion` / `schemaVersion` / `mode` / `gamePatch` / `compiledAt` / `contentPolicy` | `demo-0.1.json` 现有字段原样透传 | 数据集版本与客户端用户状态 schemaVersion 含义不同（PRD 11.3），不混用 |
| `dataMode` | 由 `dataset.mode=demo` 映射为 PRD 13.1 的 `simulated` | 模拟与来源快照（`source-snapshot` / `authorized`）永不混发（见 5.2） |
| `snapshots` / `coverage` / `defaultSnapshotId` | PRD 13.1 Dataset / Snapshot / Coverage 结构预留 | demo 数据无对应内容，返回空数组 / null / null，不编造 |
| `publishedAt` / `contentChecksum` / `fileSizeBytes` / `downloadUrl` / `minClientSchemaVersion` | **新增假设，待产品确认** | 服务端发布时生成。`minClientSchemaVersion` 供**客户端自检**：客户端 schemaVersion 低于该值时不下载新包并提示（保留旧数据）；服务端不做拦截，latest / download 均不引入客户端版本入参 |

### 3.6 下载接口

- `GET /api/v1/datasets/demo-0.1/download` → `Content-Type: application/json`，`ETag: "sha256:…"`，`Cache-Control: public, max-age=31536000, immutable`（同一 datasetVersion 内容不可变）。
- 响应体即 `demo-0.1.json` 文件原样字节；客户端校验 sha256 与元信息一致后才切换本地数据。

## 4. 数据模型

### 4.1 内容数据结构与 `demo-0.1.json` 字段映射

数据包即现有 `demo-0.1.json` 的整体结构，后端领域模型与其一一对应（`domain.content`），缺失即 null：

| JSON 路径 | 领域模型 | 关键字段与口径 |
| --- | --- | --- |
| 根对象 `schemaVersion` | `ContentBundle` | 数据格式版本，当前 1 |
| `dataset` | `DatasetMeta` | `datasetVersion`、`mode`、`compiledAt`、`sourceIds`、`gamePatch`（当前 null，未知不编造） |
| `contentPolicy` | `ContentPolicy` | `verifiedMeaning` / `pendingMeaning` / `stats` / `recommendations` / `imagePathBase` / `lowSampleThreshold=200`（透传给客户端做低样本展示规则） |
| `champions[8]` | `Champion` | `id`、`name`、`title`、`roles`、`aliases`、`pinyin`、`initials`、`displayOrder`、`iconPath`、`imageWidth/Height`、`assetKey`、`overview(+IsExample)`、`balanceNote/balanceStatus`、`skillPriority(+IsExample/Note)`、`summonerSpells[id 引用]`、`stats`（当前全 null → 客户端显示「暂无统计」）、`isStale`、`sourceIds` |

| `summonerSpells[3]` | `SummonerSpell` | `id`、`name`、`iconPath`、`assetKey`、`sourceIds` |

`championAugments[].stats` 当前实际只有 2 条模拟记录（亚索×弹跳蜜蜂 260/500，亚索×秘术冲拳 39/75），字段为 `{wins, games, isSimulated, gamePatch, segment}`；后端透传，不排序、不聚合、不推导胜率。

### 4.2 版本字段

| 字段 | 规则 |
| --- | --- |
| `datasetVersion` | 命名规则固定为正则 `^[a-z0-9]+-[0-9]+\.[0-9]+$`（模式段-主.次；模式段当前取值 `demo`，来源快照包建议 `snapshot`），如 `demo-0.1`、`demo-0.2`、`snapshot-1.0`；字符串 ID，全局唯一，发布后内容不可变。`40001` 参数校验与 `common.util` 使用同一正则，实现不得另行发挥 |
| `schemaVersion` | 数据格式版本（当前 1）；升级需显式映射与迁移，不做隐式升级（对齐 PRD 13.3） |
| `gamePatch` | 游戏版本，demo 阶段为 null；未知不编造 |
| `publishedAt` / `contentChecksum` / `fileSizeBytes` / `minClientSchemaVersion` | **新增假设，待产品确认**：服务端发布时生成；校验和用于客户端完整性校验与 ETag |

### 4.3 来源与核对状态字段

- 来源追溯：各对象 `sourceIds` → `sources[]`（含 `licenseNote`，图片与素材授权边界随来源记录一起下发，供客户端「数据说明」页使用）。
- 核对状态字段（全部透传、由客户端按 PRD R09 展示）：`effectStatus`（verified/pending）、`balanceStatus`（pending）、`stageStatus`（source-page-only）、`isStale`、`isExample`（人工示例标识：overview / skillPriority / summonerSpells / reason / build 均有独立 IsExample）。
- 模拟统计标识：`stats.isSimulated=true` + `stats.segment`（当前为「练习样本」）。

### 4.4 预留结构（不实现，仅建模占位）

PRD 13.1/13.2 的 `Snapshot`（dataMode/gamePatch/segment/windowStart…）、`Coverage`（expectedCount/includedCount/rankedCount/missingStatsCount/exclusions）与完整统计记录（`scopeType` 七种、`interactionPolicy`、`selectionMetricId`、`baselineRecordId` 等）在 `domain.stats` 预留模型定义。demo-0.1 无对应数据，接口返回空/null；待内容侧按 PRD 13 节整理出这些数据后启用，不由后端反向构造。

## 5. 内容更新链路

### 5.1 流程

```
人工内容整理（JSON，demo-0.1.json 模式）
        │
        ▼
发布校验（随 jar 提供的 CLI 发布入口，见 5.2；无 HTTP 写接口）
        │  通过 → 生成数据包文件 {datasetVersion}.json + sha256
        ▼
放入 content/ 目录（按版本并存，不可变）
        │
        ▼
原子切换 latest 指针（latest.json 写临时文件后 rename）
        │
        ▼
客户端启动 / 手动检查 → GET /datasets/latest
        │  本地版本 ≠ 服务端版本 → GET /download → 校验 sha256
        ▼
校验通过 → 写入客户端本地缓存 → 切换当前数据包
校验失败 / 网络失败 → 保留旧数据并提示（对齐 PRD R14：切换失败保留原范围与内容）
        │
        ▼
App 兜底：始终内置打包 assets 数据（demo-0.1），首次安装与更新失败均可离线使用
```

- 后端不做推送，客户端按启动时机拉取 latest；不做增量更新，整包原子下发（当前包仅 ~50KB，增量收益为负）。
- 同一 `datasetVersion` 发布后内容不可变（immutable）；更正内容必须发新版本号，保证校验和可追溯。
- 发布入口的实现载体固定：随 jar 提供的 **CLI 命令**（Spring 命令行入口，形如 `--publish <数据包文件> [--allow-broken-references]`），校验规则实现在 service 层、由 CLI 调用；由服务器本地或 CI 执行，不暴露任何 HTTP 写接口。

### 5.2 一致性策略（发布校验）

对齐 PRD 13.3「导入边界」与 12.2「聚合与空值」：

1. **结构校验**：数据包符合 JSON Schema（`resources/schema/` 维护）；schemaVersion 未知则拒绝。
2. **引用闭合**：`championAugments` 的 championId/augmentId、`builds` 的全部 itemId、`summonerSpells` 引用必须存在于同包清单。正常数据包存在悬空引用则**拒绝发布**；验收夹具包（PRD 13.3 的坏 ID 用例）通过显式发布参数 `allowBrokenReferences` 发布并自动标记，不与正常包混放。
3. **计数有效性**：`stats` 存在 wins/games 时必须 `games > 0` 且 `0 ≤ wins ≤ games`；违规记录标记 invalid 并隔离进发布报告，不自动修成 0（对齐 PRD 12.2）。
4. **单一数据模式**：一个数据包只允许一种 dataMode；`isSimulated=true` 的统计只能出现在 simulated 包，source-snapshot 包禁止混入模拟记录（对齐 PRD 22 系用例 V22 模式隔离）。
5. **唯一性**：各清单内 id 唯一，全局 assetKey 唯一。

发布报告随数据包归档（`content/reports/{datasetVersion}.report.json`），覆盖缺口可查（对齐 PRD R11）。

### 5.3 模拟统计口径的处理

- 后端**只透传原始字段**（wins、games、isSimulated、segment、gamePatch、contentPolicy.lowSampleThreshold），不计算、不聚合、不排序任何胜率 / 选取率 / 差值字段。
- 胜率、低样本（games<200）、「样本未知」、胜率差（百分点）等全部由客户端按 PRD 12 章规则计算展示；PRD 明确「缺失不是零」「无有效记录为 null」，后端保持 null 原样下发。
- 模拟包（demo-0.1）与未来来源快照包分版本发布，绝不混入同一 datasetVersion（对齐需求说明 6.1：模拟与快照分开存放、展示和排序）。

## 6. 非功能

### 6.1 鉴权边界

- MVP 无账号体系，接口全部**只读公开**，不引入 token / 网关（PRD 不纳入登录，新增鉴权属过度设计）。
- 写路径不暴露：内容发布通过随 jar 提供的 CLI 发布入口（见 5.1），由服务器本地 / CI 调用，无 HTTP 写接口。
- 远期若内容包含未公开素材需保护下载链接，可增加短期签名 URL——**新增假设，待产品确认**，MVP 不做。

### 6.2 缓存

- `latest` 接口：`Cache-Control: max-age=60`，避免高频轮询直穿；内容小、变化低频。
- `download` 接口：`ETag = sha256` + `If-None-Match` → 304；`Cache-Control: immutable`（datasetVersion 不可变）。
- 客户端侧：已下载数据包本地缓存，离线可用；`assets/data` 内置包为最终兜底。
- 服务端进程内缓存 latest 元信息，指针文件变更时失效；MVP 不引入 Redis。

### 6.3 灰度与回滚

- **回滚**：`content/` 内各版本数据包并存，`latest.json` 指针单文件控制指向；回滚 = 指针切回旧版本（原子 rename），秒级生效，无数据损失。
- **灰度**：按客户端版本 / 渠道下发不同 datasetVersion（MVP 不做——**新增假设，待产品确认**；实现时在 latest 接口增加可选请求参数，默认全量一致）。
- 校验失败的新包不会成为 latest：发布校验在指针切换之前，天然挡住坏包上线。

### 6.4 部署形态与依赖边界

- 形态：单实例 Spring Boot 可执行 jar + 同机 `content/` 目录；客户端直连。
- 下载流量增大后，可将 `content/` 前置 nginx / CDN 静态化（同生态常规做法，仅静态文件分发，API 仍在应用内）——非新中间件引入。
- **不引入数据库 / 缓存中间件**的理由：内容为低频发布的不可变版本化文件，文件系统 + 校验和天然满足一致性；PRD 未定义任何需要在线写入的内容管理能力。引入 DB 的触发条件（届时另行评审）：①内容编辑后台立项（多人协作维护内容）；②数据包规模显著增长需要结构化检索。备选：SQLite/MySQL + Flyway，属常规 Java/Spring 生态扩展。

### 6.5 可观测与安全基线

- 健康检查供探活；访问日志按需开启；错误信息不泄露本机敏感路径、凭据或内部调用细节（对齐 PRD 14）。
- 数据包只含公开整理内容与本地相对图片路径；图片仍随 App 打包，后端不托管图片。
